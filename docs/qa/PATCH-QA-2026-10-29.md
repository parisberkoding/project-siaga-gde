## 3. Perubahan teknis utama

### SPD (MoM #5)
- Migrasi `2026_10_29_000001_change_nomor_urut_to_integer_on_surat_spds_table`:
  `nomor_urut` varchar → unsigned integer, backfill aman (MySQL & SQLite), `down()` tersedia.
- `SuratSpd::generateNomorSurat()` menghitung maksimum **numerik** (bukan urut teks)
  dan melewati nomor yang sudah terpakai.
- `SuratSpd::createWithNumberedSurat()` memakai `Cache::lock` + retry pada
  unique violation; dipakai `storeSurat`, `storeSuratSuperadmin`, `createExtension`.
- `createExtension()` menyalin `unit_id` (fallback unit pembuat), `parent_surat_id`
  menunjuk surat **sebelumnya** (bukan root), dan `total_budget` dihitung eksplisit
  (kolom `budget_per_hari` memang sudah tidak ada di skema).
- `SuratSpdExtension::approve()` mempropagasi `tanggal_kembali`, `lpj_deadline`,
  akumulasi `total_budget`, `extension_count`, serta mencatat
  `SuratSpdFundAddition` — idempoten.
- `showSuratSuperadmin` / `approveSurat` / `rejectSurat` memakai
  `UnitScope::ensureUnit()`; antrean perpanjangan memakai `inUnit()`.
- `printSurat` menerima `approved` **dan** `completed`; visibilitas lewat
  `SuratSpd::isVisibleToUser()` (pemilik/penumpang/peran pengelola unit/global).
- 9 catch block tidak lagi membocorkan `$e->getMessage()` (dicatat ke log).
- Cascade delete: detail, budget/pencairan, QR, log perpanjangan, laporan harian,
  fund addition.

### BBM (MoM #1)
- `VoucherExpiryService::expireStale()` (baru) — idempoten, chunked, transaksi per
  voucher, mencakup status `active` maupun `approved`; dijalankan lazy + scheduler
  `bbm-expire-vouchers` tiap 10 menit.
- Pelaporan pembelian menolak voucher tidak ada/kedaluwarsa **sebelum** menyimpan
  apa pun (`requester_submit_report`, `requester_upload_proof`, `storeOperational`).
- JS `pelaporan/index.blade.php`: `syncHiddenFields()` dijalankan ulang saat isian
  manual berubah dan sekali lagi sebelum submit; server punya fallback nominal.
- Catatan approval → `approval_notes` (single, bulk, bulk superadmin).
- Approve/reject single & bulk memakai `inUnit()`; bulk menghitung unit lain
  sebagai "dilewati".
- `voucherExport()` memakai `inUnit()` dan memfilter `ids` luar unit.
- `requester_create()` memakai `Cache::lock('bbm-request-{user}')` + dedup 60 detik.
- Foto laporan cepat dikompres via `ImageCompressor` (fallback `storeAs`).

### Dashboard BBM (MoM #4)
- Semua dataset & opsi filter memakai `UnitScope`.
- Kartu ringkasan memakai rentang tanggal eksplisit; label dinamis.
- Link periode/filter tetap di route dashboard modul.
- Tombol Export CSV (`bbm.export`) & Trip Analysis (`vehicle.report`) digate.

### Lain-lain

- `ModuleContext::SHARED_ROUTES` + `lunch.attendance.*` (absensi QR publik).

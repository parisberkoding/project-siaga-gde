Arsitektur & Teknologi

Bagian ini memaparkan tumpukan teknologi, pola arsitektur berlapis, komponen aplikasi yang berukuran besar, struktur direktori, integrasi eksternal, dan catatan deployment SIAGA sebagai konteks teknis bagi seluruh desain pada bagian berikutnya.

Tumpukan teknologi

SIAGA dibangun sebagai aplikasi monolitik Laravel dengan rendering sisi server (Blade) dan peningkatan progresif pada sisi klien. Tabel berikut merangkum lapisan teknologi beserta perannya.

Bahasa PHP 8.2+ composer ^8.2 Container Docker memakai php:8.4-apache; ekstensi pdo_mysql, gd, zip, bcmath, intl, exif, dan mbstring diaktifkan.
Basis data MySQL / MariaDB melalui Eloquent ORM Logika query dibuat kompatibel SQLite untuk kebutuhan pengujian otomatis.

Pola arsitektur

SIAGA mengikuti pola MVC Laravel dengan penambahan service layer untuk domain katering. Permintaan mengalir dari rute menuju middleware, lalu ke controller; controller memanggil model Eloquent atau service, dan hasilnya dikembalikan sebagai tampilan Blade. Berikut rincian pola yang dipakai.

  1. Routing terpusat di routes/web.php

    Seluruh rute web utama terdaftar dalam satu berkas dan dikelompokkan per prefix domain serta dilindungi middleware pada tingkat grup.

  2. Pemisahan controller per jenis pengecekan

    Pengecekan harian, mingguan, bulanan, dan body dikelola controller terpisah (DailyCheckingController, WeeklyCheckingController, MonthlyCheckingController, BodyCheckingController) agar berkas tetap ramping dan mudah dipelihara.

  3. Service layer pada modul Lunch

    Logika katering dipisahkan ke lima layanan: IdentityResolutionService (resolusi QR dan alias ke pekerja), LearningService (pembelajaran pola historis), LunchDistributionService (penyusunan porsi terkunci untuk vendor), LunchForecastService (mesin forecast H+1), dan NameNormalizer (normalisasi nama untuk pencocokan kemiripan).

  4. Middleware CheckPermission (RBAC v2) dan checkrole (legacy)

    CheckPermission memeriksa permission granular seperti bbm.request atau spd.manage; checkrole (kelas CheckRole, alias role) dipertahankan untuk pemeriksaan peran lama seperti role:superadmin.

  5. Strategi dual-write peran

    Kolom user.role dan tabel user_roles dipelihara bersamaan sehingga data peran lama tetap kompatibel selama migrasi ke RBAC v2 berlangsung.

Risiko ukuran berkas Angka baris di atas berasal dari catatan DOKUMENTASI_PROJECT.md bagian 4 dan bersifat perkiraan. app/

Inti aplikasi: controller, model, middleware, service, command, dan export.

  • Http/Controllers/Lunch/ memuat sembilan sub-controller katering; logika beratnya didelegasikan ke Services/Lunch/.
  • Services/ menampung integrasi eksternal (AI, harga BBM) dan pengolahan gambar.
  • Console/Commands/ memuat perintah terjadwal untuk forecast katering dan sinkronisasi harga BBM.

resources/ dan routes/

Presentasi dan titik masuk aplikasi.

  • resources/views/ dikelompokkan per peran: admin/, dispatcher/, requester/, superadmin/, lunch/, manager/, dan templates/.
  • partials/ menampung komponen bersama seperti navbar, sidebar, dan footer.
  • routes/web.php menjadi sumber tunggal pemetaan URL ke controller; routes/console.php mendefinisikan penjadwalan tugas.
Kaidah penempatan berkas Fitur baru mengikuti pola yang ada: rute pada routes/web.php, controller sesuai domain, logika lintas-domain pada app/Services/, dan tampilan pada folder peran di resources/views/.

Integrasi eksternal

SIAGA berinteraksi dengan layanan luar untuk fungsi yang tidak dibangun sendiri. Seluruh kredensial disimpan melalui berkas .env dan dibaca melalui berkas konfigurasi, bukan ditulis langsung di dalam kode.

IntegrasiTujuanMekanisme & titik kode
AI OCR struk BBM Mengekstrak nominal dan jenis BBM dari foto struk belanja secara otomatis. Vision-language model gemini-3.1-flash-lite melalui endpoint OpenAI-compatible; dipanggil dari ImageAnalysisService dan rute POST /analyze-struk (ReportingController) yang dibatasi throttle:10,1 dan permission pelaporan.analyze.
AI Assistant Gaga Menjawab pertanyaan operasional atas data nyata melalui antarmuka percakapan. API Groq model llama-3.3-70b-versatile melalui client OpenAI-compatible (config/services.php bagian groq); dilayani AiAssistantController dan GeminiAssistantService, dengan Data Mart sembilan domain (permohonan BBM, kendaraan, driver, harga bensin, SPD, LPJ, katering, suku cadang, pengecekan).
Sinkronisasi harga BBM Menjaga master harga BBM resmi tetap mutakhir tanpa input manual harian. Perintah terjadwal gasoline:sync memanggil GasolinePriceSyncService dan menyinkronkan harga berbasis province_slug masing-masing site; dijadwalkan setiap pukul 06:00 pada routes/console.php.
Penyimpanan berkas terproteksi Menyajikan bukti transaksi, kuitansi, odometer, dan QR code tanpa membuka storage/ secara publik. Rute GET /files/storage/{path} ditangani StorageFileController; hanya berkas di dalam storage/app/public dilayani dan path traversal ditolak, dengan mime SVG dikoreksi agar QR dapat dirender.
QR code & barcode Tanda tangan digital dan pencatatan kehadiran tanpa input manual. endroid/qr-code dan BaconQrCode untuk tanda tangan SPD serta absensi makan siang; picqer/php-barcode-generator untuk barcode kendaraan; halaman absensi publik diakses melalui /lunch-attendance/*.
Verifikasi model dan kredensial PRD menyebut model OCR gemini-3.1-flash-lite, sedangkan berkas konfigurasi (config/imageanalysis.php) mengambil nama model dari variabel lingkungan GEMINI_MODEL dengan nilai bawaan gemini-2.0-flash. Nama model dan ketersediaan kunci API pada lingkungan produksi wajib diverifikasi langsung ke .env dan konfigurasi config/services.php.

Catatan deployment

Langkah berikut merupakan urutan umum penyiapan aplikasi pada lingkungan baru. Perintah dijalankan dari akar proyek.

  1. Menyiapkan konfigurasi lingkungan

    Salin .env.example menjadi .env, lalu sesuaikan koneksi basis data, kunci aplikasi, kunci API AI, dan parameter katering (SIAGA_FORECAST_AT, SIAGA_LUNCH_START, SIAGA_LUNCH_END).

  2. Memasang dependensi PHP

    composer install untuk mengunduh seluruh paket sesuai composer.lock.

  3. Menjalankan migrasi basis data

    php artisan migrate untuk membentuk skema, dilanjutkan seeder data awal bila diperlukan.

  4. Membuat tautan penyimpanan

    php artisan storage:link agar berkas yang disajikan melalui perantara tersedia pada sistem berkas publik aplikasi.

  5. Membangun aset frontend

    npm install lalu npm run build untuk menghasilkan bundel Vite produksi.

  6. Menjalankan penjadwal

    Scheduler menjalankan lunch:generate-forecast setiap pukul 15:00 (dapat diubah melalui config/siaga.php dan routes/console.php) serta gasoline:sync setiap pukul 06:00. Pada lingkungan kontainer dijalankan layanan scheduler dengan perintah php artisan schedule:work.

  7. Menjalankan melalui Docker (opsional)

    Repositori menyediakan Dockerfile (build aset Vite, runtime php:8.4-apache) dan docker-compose.yml dengan layanan app, db (MySQL 8.4), serta scheduler yang diaktifkan melalui profil.

Perlu verifikasi Detail deployment di atas disusun dari berkas Dockerfile, docker-compose.yml, routes/console.php, dan composer.json. Nilai aktual — nama basis data, port, kredensial, jadwal scheduler, serta konfigurasi antrean dan cache — bergantung pada berkas .env dan kebijakan infrastruktur setempat, sehingga seluruh langkah ini wajib diverifikasi ulang pada lingkungan target sebelum eksekusi.
